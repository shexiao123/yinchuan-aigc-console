### 原型的两种形态

原型是单文件 HTML，零外部依赖。**桌面端**显示手机模型（带刘海和假状态栏）用于演示；**真机打开**（≤700px 宽）自动去掉外框，内容铺满全屏，底部标签栏避开全面屏手势条。

所以同一个链接，电脑上是「模型展示」，手机上就是「真机体验」——不需要两个版本。

### 宣传样片

每个服务都可挂宣传样片（视频 / 图片），客户在服务详情页直接看片，这是最关键的转化环节。

**服务者上传**：
- 网页版：接单工作台 → 我的服务 → 「上传样片」按钮 → 可多选文件，一次批量传
- 小程序：接单工作台 → 我的服务 → 「上传样片」→ 选「上传视频样片」或「上传图片样片」

限制：视频不超过 100MB，图片不超过 10MB。支持 MP4 / MOV / M4V / WebM，JPG / PNG / WebP。

**客户观看**：
- 登录后：网页版点样片弹层全屏播放（图片新窗口打开），小程序点样片调起全屏预览
- 未登录：显示样片卡片与「登录后观看」提示，点一下引导登录（云存储的签名链接必须登录才能生成，这是平台限制）

**管理端**：服务与分类页能看到每个服务的样片数量，可查看和删除违规样片。

### 管理端功能

深色侧栏 + 9 个模块：

- **运营概览**：成交额、订单量、服务者数、在架服务 4 个 KPI + 近 7 天订单趋势图 + 分类分布 + 热销 Top5 + 待处理事项
- **订单管理**：搜索、按状态筛选、**改订单状态**（会记入操作日志）
- **结算与提现**：按已完成订单生成结算单（自动算抽成）、标记打款
- **服务者管理**：查看全部服务者、**认证 / 取消认证**
- **入驻审核**：审核服务者申请，通过即自动开通服务者身份
- **服务与分类**：服务上下架、编辑分类名称与图标
- **首页与内容**：轮播位增删改
- **平台设置**：抽成比例、最低下单金额、客服电话、平台规则文案
- **操作日志**：所有写操作留痕

### 首次运行步骤

1. 用微信开发者工具「导入项目」，目录选择 `miniprogram/`。
2. AppID 处选择「测试号」，或填入你自己的小程序 AppID。
3. 工具栏点击「工具 → 构建 npm」。这一步会把云服务 SDK 装到 `miniprogram_npm/`，**必须执行**，否则真机运行会报模块找不到。

> 若需要重新安装，在本目录执行 `npm install` 后再点「构建 npm」。

4. 点击「编译」，模拟器即可运行。

### 登录说明

小程序使用微信授权登录（`wx.login` + 云服务 `signInWithWechat`）。

首次使用需要：

1. 在 WorkBuddy 管理后台的该应用下完成「小程序绑定」并开启微信登录开关；
2. 在小程序代码里，`utils/cloud.js` 已写好本应用的 `endpoint` 与 `publishableKey`，无需修改。

**H5 预览无法完成真实微信登录**——预览面板拿不到真正的 `wx.login` 凭证，这是预览能力本身的限制，不是代码缺陷。登录需要在授权的小程序里验证。

## 四、两套线上环境的关系

**重要：网页版和小程序目前是两个独立的云环境，数据不互通。**

原因：云服务的一个应用对应一个独立的数据环境，网页版和小程序是两个不同的应用（各自有独立的登录身份、域名和数据）。

| | 网页版 | 小程序 |
|---|---|---|
| 应用 ID | `wbapp_ljDFUAeoNoNPMqrfAZpbEV` | `wbapp_NPfdYpGfbDWvkcfEnOHVJB` |
| 访问地址 | `guangying-web.app.workbuddy.host` | 微信内使用 |
| 登录方式 | 手机号验证码 / 微信扫码 | 微信授权 |
| 数据表 | 8 张，结构与策略完全一致 | 同左 |

两边表结构、字段、RLS 策略（21 条）逐条核对一致，业务代码也共用同一套 API 调用约定。**如果你需要两端数据实时互通**，有两条路：

1. 让其中一端成为唯一数据源，另一端通过接口读取（需要额外开发一层同步服务）
2. 放弃小程序，只用网页版（电脑手机浏览器都能用，功能完全一致）

考虑到微信小程序的流量价值（便于分享、扫码进店），我的建议是保留两端，订单数据以小程序为主库，网页版作为管理端——但这需要你先定哪一端是主库。

## 五、数据模型

云数据库共 8 张表，全部开启行级安全（RLS）。前端不做权限判断，安全边界在数据库。

| 表 | 用途 | 可见性 |
|---|---|---|
| `categories` | 服务分类 | 公开读 |
| `banners` | 首页轮播 | 公开读 |
| `platform_settings` | 抽成比例、最低金额、客服电话 | 公开读 |
| `staff` | 平台管理员名单 | 公开读 |
| `providers` | 服务者档案 | 公开读；本人可改自己的 |
| `services` | 服务商品 | 已上架公开读；本人可增改自己的 |
| `orders` | 订单 | 客户、服务者本人、平台管理员可见 |
| `reviews` | 评价 | 公开读；本人可写 |

关键设计：

- `orders.provider_id` 允许为空——为空表示「公开需求」，任何服务者可在需求大厅抢单。
- `orders.provider_owner_id` 由数据库触发器自动写入，前端不传，防止伪造接单方。
- 抢单用带条件的更新（`provider_id is null` + `select()` 回读），并发下只有一人能抢到。
- 金额一律以「分」为单位存储，展示时才除以 100。

### 平台管理员

后台管理页仅对 `staff` 表中的账号开放。把你的账号 uid 插入 `staff` 表即可：

```sql
INSERT INTO staff (uid, name, role) VALUES ('<你的uid>', '管理员', 'admin');
```

uid 在小程序里可以通过 `getApp().globalData.session.user.id` 取到，在网页版里通过 `window.API.getSession()` 拿到。
